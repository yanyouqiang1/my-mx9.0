# 键盘宠物（scr_pet）设计

> 状态：**设计阶段，未动固件一行代码**。本文里的行号全部来自 `src/lvgl_s3.ino`
> 当前工作区（9741 行）。配套屏效草图：`python3 mock_pet.py` →
> `mock_pet.png`（全屏三姿态）/ `mock_pet_peek.png`（随机探头）。

## 已定的决策

| 决策 | 结论 |

| 造型 | **就用橘猫**（`mock_pet.png` 那个），纯 `lv_obj` 基本图形拼 |

## 0. 结论先行

能做，而且**成本比想象低**——因为这套固件里已经躺着一整套"宠物需要的事件源"，
只是没人把它们接到一块屏幕上：

| 宠物需要什么 | 固件里现成的 | 位置 |
| --- | --- | --- |
| 感知"你在打字" | 按键去抖后的唯一全局钩子 | `triggerKeyReaction()` 调用点 `5886` |
| 感知"你离开多久了" | `lastActivityTime` + 闲置分钟数 | `605` / `5854` |
| 感知"你今天多忙" | KPM 环形缓冲 / 今日击键 / 累计击键 | `610-617` |
| 感知冷热 | SHT31 温湿度 | 已有曲线在跑 |
| 感知"现在几点" | `localtime`（**注意：只靠 BLE 对时，无 NTP**） | `9242-9252` |
| 说话 | HUD 单例 / 通知队列 / `NOTIFY:` `ALERT:` | `3486` / `3542` / `8093` |
| 手机/电脑喂它 | `btLinkSend*` 反向推送 + 网页 `sendBLE` | `bt_link.h:204` |
| 摸摸它 | C3 旋钮 `ROT:R/L` + 按键 | `8118` |

要新写的：**角色绘制、状态机、台词表、矩阵长按检测、出场仲裁**。
后两项是"随机探头"这个需求带出来的，见 §4 和 §6。

## 1. 形态选型：四条路，选哪条

240×240 要同时装下时钟和宠物，这是设计的真正矛盾点。四种做法：

### A. 当第 8 种主屏风格（`DISP_MODE_PET = 7`）

`currentDispMode` 加一档，切风格时切过去。

- ✅ 生命周期是现成的：`renderCurrentDisplayBase()` 建、`gotoMainScreen()` 退
- ❌ 宠物一出现，时钟/温湿度/击键统计就全没了
- ⚠️ 要改 3 个"漏了必崩"的地方：`renderCurrentDisplayBase()` 的删除段
  （`8891-8907`）、`resetStylePointers()`（`1392-1447`）、`destroyMainScreen()`
  （`1448-1452`）。三处漏一行 = `updateDynamicElements()` 往野指针写 = 踩堆重启。
  这不是退化，是确定崩。

### B. 当 `lv_layer_top()` 上的常驻小挂件

40×40 的宠物挂在主屏角落，压在任意一种风格上面。

- ✅ 时钟还在，"它一直陪着你"的感觉最强
- ❌ **7 种风格的版面都得给它让位置**，等于改 7 套布局
- ❌ 和 HUD / 通知面板 / 响铃卡片抢同一层。`lv_layer_top()` 现在已经有三个对象
  （`3449` / `3601` / `3827`），源码里**没有仲裁**——谁后建谁在上面，
  响铃浮层要是被小宠物压住，就是"闹钟响了但看不见"
- ❌ 40×40 太小，画不出"活物"

### C. 独立一屏 + 屏保再占一档

```
交互模式：菜单 → 宠物   → scr_pet 全屏，随便摸随便聊
待机模式：闲置 60s      → 宠物出现在屏保（"它发现你不在，在等你"）
```

- ✅ 240×240 全部让给它，一只 110×112 的猫放得下（见 `mock_pet.png`）
- ✅ **7 种主屏风格一行都不用改**
- ✅ 生命周期挂在两套现成机制上：`SYS_MODE_*` 换屏（`showScreen/swapScreen`
  `1098`/`1113`）+ `enterScreensaver()`
- ❌ 宠物不在主屏上常驻（这是接受的代价：换来 0 冲突）

### D. 底部横条"探头"（随机打招呼用）

底部 72px 高的浮层，盖在主屏**底部**（`y=168..240`），猫头从横条上探出来。

- ✅ 主屏 7 种风格的内容重心都在中上部，**底部是唯一不打架的位置**
- ✅ 这才是"它会跟你打招呼"最直接的兑现形态——你正在用电脑，屏幕底边
  悄悄探出一个猫头说句话，5~8 秒后自己缩回去
- ✅ 临时浮层 ≠ 常驻挂件：B 的问题（版面冲突 / 抢层）只在"一直在"时成立
- ❌ 要处理和 HUD、通知面板、响铃卡片的优先级（源码现在没有仲裁，见 §4）
- ❌ 会短暂占用底部一小块（高对比度风格的底部状态条 `y=178..236` 会被盖住，
  所以探头期间那几秒看不到温湿度条——可接受，横条自己就带完整信息）

**选 C + D 组合，否决 A 和 B。**
C 负责"我主动去找它玩"，D 负责"它主动来找我玩"。两者互斥，由 §4 的
`petGate()` 统一裁决。顺带把宠物加成 `SAVER_PET = 4`——README 已经写明屏保
档位编号**只能往后追加、不能往前插**（`saver_mode` 是 NVS 持久化的），
所以是追加 4，`SAVER_OFF = 3` 一字不动。

## 2. 它长什么样：绘图能力倒推出造型

这套固件的绘图能力是被 LVGL 配置和历史坑共同限死的，造型必须顺着它长：

| 约束 | 事实 | 对造型的影响 |
| --- | --- | --- |
| `LV_COLOR_SCREEN_TRANSP = 0` | 需要 alpha 的中间图层被静默丢弃（README:88-92） | 宠物**不能有半透明发光**，阴影只能靠 `shadow_opa`（锁灯呼吸 `8740-8749` 已经这么用） |
| 不能用 `transform_zoom` / `transform_angle` | 同上 | **画不出三角形**。所以耳朵是圆的。想换尖耳得上 `lv_line` 三点折线 |
| `LV_USE_CANVAS = 0`，GIF/PNG/BMP 全 0 | `lv_conf.h:64-90` | 上传序列帧当动画这条路要自己加解码器，**v1 不走** |
| 现有 `lv_img` 全是 `TRUE_COLOR` 无 alpha | `profile_icons.h:1857` 等 | 精灵图没有透明通道，贴上去是个色块方框 |
| 单缓冲 30fps | `LV_DISP_DEF_REFR_PERIOD 33` | 动画按 33ms 走，别再开第三条刷屏路径 |

**结论：v1 纯 `lv_obj` 基本图形拼。** 圆 = `radius LV_RADIUS_CIRCLE`，
圆角矩形 = `radius`，线 = 细矩形或 `lv_line`，色块 = 背景色。
和现有的 Windows/苹果图标（`topIconWin[]`/`topIconMac[]`）是同一套路子，
**零新增资源、零新增 RAM、零解码器**。草图见 `mock_pet.png` 三姿态。

### v2 升级路线：像素精灵 + 自定义 draw 回调

想让它更像"像素小人"（Tamagotchi 那种）就用 `LV_EVENT_DRAW` 回调
+ 1bpp 位图 + 4 色调色板：32×32 = 128 字节/帧，8 帧 1KB flash。
项目里从没用过事件回调（`lv_obj_add_event_cb` 命中 0 次），属于新范式，
风险中等，但比"自己实现 GIF 解码器"干净得多。

## 3. 竖向预算（草图第一版就撞了这个）

```
0   ─┬─ 顶栏：宠物名 + 心情条 28px
    │
56  ─┼─ 猫头顶
    │   猫 110×112（脚底影子 166）
168 ─┼─ 对话气泡顶
    │   气泡 168..218，行盒 simsun_16_cjk = 19px
219 ─┼─ 按键提示行（19px）
240 ─┴─
```

**硬结论：全屏台词最多 2 行 × 13 个汉字 = 26 字。** 气泡宽 216px、汉字 16px，
`216 / 16 = 13.5`。加文案前先跑 `python text_width.py "你的文案"`，
超 216px 就是放不下（README:256）。第 3 行会直接压到提示行上——
草图第一版就是这么重叠的。

### 探头横条的预算（草图第一版也撞了这个）

```
168 ─┼─ 横条顶
    │   台词区 x=64..232 = 168px -> 每行 10 字
    │   行1 白 / 行2 dim / 行3 dim（关闭提示）+ ✕ 在行3 右端
240 ─┴─  72 / 19 = 3.8 -> 只装得下 3 行
```

所以探头台词是 **2 行 × 10 字 = 20 字**，第 3 行固定留给"长按 LOGO 收起我"。

**✕ 不能放右上角**：会吃掉台词第一行的宽度。放提示行右端，
整个 168px 都能给台词——草图第二版才排开的。

猫头只画到下巴（`y=178..218`，r=26，中心 `(36,204)`），肩膀在横条之外，
视觉上就是"从屏幕底边探出来"，而不是"浮在屏上的一个圆"。

## 4. 出场仲裁：一个 scene 状态，四种形态

"随机探头"这个需求把设计从"一个页面"变成了"一个会自己找你的东西"，
于是最关键的新东西是**什么时候该出现、什么时候必须闭嘴**。

```c
enum PetScene { SCENE_NONE = 0,   // 不在场
                SCENE_PEEK,       // 底部横条探头，固定 8s 自动消失
                SCENE_FULL,       // 全屏宠物页（菜单 / 长按 LOGO 进）
                SCENE_SAVER };    // 屏保里的宠物（闲置 60s+）
static PetScene petScene = SCENE_NONE;
```

**四种形态互斥，同一时刻只有一个。** 仲裁集中在**一个**函数里——
照 `updateCountdownVisibility()`（`3958`）的教训：分散判断迟早漏一处，
表现就是"进了菜单底下还是倒计时"。

```c
// 返回当前允许的场景；调用方据此建/拆对象。
// 顺序有讲究：SCENE_FULL 必须排在"界面态"这条**前面**——
// 宠物全屏页自己就是 SYS_MODE_PET（!= SYS_MODE_NORMAL），
// 放在后面的话永远走不到，用户一进宠物页它就把自己关掉了。
static PetScene petGate(void) {
    if (ringingKind != RING_NONE)            return SCENE_NONE;  // 响铃压过一切
    if (petScene == SCENE_FULL)             return SCENE_FULL;  // 用户主动进的不踢出去
    if (currentSysMode != SYS_MODE_NORMAL)  return SCENE_NONE;  // 菜单/设置/录制/日志
    if (countdownShown && timerRunning)     return SCENE_NONE;  // 倒计时全屏
    if (notifCount > 0)                     return SCENE_NONE;  // 通知告警
    if (millis() - lastActivityTime < 3000)  return SCENE_NONE;  // 刚敲过键，别打断
    if (millis() - lastActivityTime > SLEEP_TIMEOUT_MS) return SCENE_SAVER;
    return petPeekAllowed() ? SCENE_PEEK : SCENE_NONE;
}
```

对应要在 `SYS_MODE_*` 后面**追加** `SYS_MODE_PET = 11`（现有的 0~10 已占满，
`462` 是最后一个 `SYS_MODE_ELOG 10`）。注意 `IS_SETTING_MODE()` 的区间是
`SYS_MODE_SET_TIME..SYS_MODE_SET_LIGHT`（`463`），**别把 PET 落进这个区间**，
否则它会被当成设置页参与界面态按键分发。

> ⚠️ **`notifCount > 0` 这一条顺手修了一个现存 bug。**
> 现在的息屏判定（`9658-9668`）条件里没有 `notifCount` —— 有未确认通知时
> 闲置进屏保，通知面板（`lv_layer_top` 上的 `scr_notif`）和屏保会同时在，
> 谁在上面靠建屏顺序，表现为"通知被壁纸盖住 / 凭空消失"。
> 宠物探头踩的是同一个坑，所以这里一起收口。

### 探头频率控制：会主动出现，但不能烦

随机探头最大的失败模式是**三天后被用户拔电**。所以频率必须是硬约束：

| 参数 | 值 | 理由 |
| --- | --- | --- |
| 总开关 | **默认开**，菜单可关 | 用户明确要默认打开 |
| 显示时段 | **可配**，默认 23:00–07:00 静默 | 夜班/倒时差的人要能改，见下 |
| 触发窗口 | 闲置 > 25s 才进候选池 | 少于 25s 人还在手边，不需要它凑上来 |
| 判定节拍 | 每 20~40s 判一次（`esp_random()` 抖间隔） | 固定间隔会被训练出"每 40 秒必有东西"的预期 |
| 触发概率 | 30% | 平均几分钟一次，不至于成噪音 |
| 每日上限 | 8 次 | 记 NVS，跨日清零照抄 `5864-5881` 的 `todayYmd` 范式 |
| 停留时长 | **固定 8s** | 用户定的。固定比随机好：用户知道"8 秒后它自己走"，不会一直盯着等 |

**时段判定的坑：跨零点。** 默认 23:00–07:00 是 `from > to`，所以判定不能写
`h >= from && h < to`（那样永远不成立）：

```c
static bool petInWindow(uint8_t h) {
    if (petFromH == petToH) return true;              // 相等 = 全天
    if (petFromH <  petToH) return h >= petFromH && h < petToH;
    return h >= petFromH || h < petToH;                // 跨零点
}
```

时段粒度只做到**小时**（0~23，两位数各一格），不做到分钟——理由见风险 13：
这台机器没有 NTP，时间只靠 BLE `TIME:` 下发，做分钟级时段判断是自欺欺人。

### 负反馈闭环：长按关掉是有后果的

用户嫌烦时必须有出口，而且**关掉要真的关掉**——不然"长按关闭"只是个装饰：

```
探头在场时长按 LOGO
    → 立即收起（本次不再出现）
    → pet_bothered++                          （NVS）
    → 连续 2 次 → 暂停主动探头 24 小时
    → HUD 提示一次："好，我安静一天"（之后不再提示）
```

反过来，探头停留期间**用户摸了它**（按键/旋钮）也算一次"被欢迎"，
`pet_bothered--`。这样"它老出现"和"它老被关"都会收敛到用户满意的那个频率。

### 底部让位：探头那 8 秒把状态条收起来

探头横条 `y=168..240`，会盖住底部。先查清**到底哪些风格会被盖**：

| 风格 | 底部内容位置 | 会被盖？ |
| --- | --- | --- |
| 高对比度 | 底部状态条 `y=178..235` | ❌ 会 |
| 壁纸 | 右下角时钟板 112×40，贴 `BOTTOM_RIGHT -10,-10` → `y=190..230` | ❌ 会 |
| 极客仪表盘 | 分区到 `y≈105` | ✅ 不会 |
| 大字时钟 | 最大 y 偏移 44 | ✅ 不会 |
| 信息面板 | 最大 y 偏移 126 | ✅ 不会 |
| 击键监控 | 最大 y 偏移 66 | ✅ 不会 |
| 律动 | 柱基线 `y = 110 - barH`，峰值 25 → `barH≤104` → `y≥6` | ✅ 不会 |

**只有 2 种风格需要处理**，这是查出来的事实而不是拍脑袋。草图对比见
`mock_pet_yield.png`（常态 / 直接盖 / 让位）——中间那张"直接盖"会把温湿度条
切掉一半、露在上半截，很丑；右边让位之后底部是干净的。

**实现上有个坑：底部条不是一棵树，是 12 个平铺对象。**
`build_style_high_contrast()` 里 `box` 只是装饰框（`2843`），温湿度标签和进度条
全是 `lv_obj_create(hc_bg)` 的**直接子对象**（`2855`/`2873`/`2877`…）。
实测清点（`2842-2930`）：10 个具名全局（`hc_lbl_strip_t/_t_val/_h/_h_val/
_chars/_chars_val` + `hc_bar_t_track/_t_fill/h_track/h_fill`）
+ 2 个 `iconRect(hc_bg,…)`（装饰框 + 竖分隔线）= **12 个**，
后两个还是 `{ }` 块里的**局部变量**，出了函数就没句柄。

所以**不要 re-parent 成一个容器**——那要把 10 个对象的 y 全从
`180/199/209/228` 改成 `2/21/31/50`，动的是用户已经逐像素调好的版面，
还正好踩上 README 里 `pad` 偏移那条雷。正确做法是**收一个指针清单**：

```c
// 让位对象清单：探头期间整组加/去 LV_OBJ_FLAG_HIDDEN
// 今天是 12 个（见上），数组开 16 留余量 —— 开 12 的话数错一个就静默越界
#define PET_YIELD_MAX 16
static lv_obj_t* petYieldObjs[PET_YIELD_MAX] = { nullptr };
static uint8_t   petYieldCount    = 0;

static void petYieldAdd(lv_obj_t* o) {
    if (o == nullptr) return;
    if (petYieldCount >= PET_YIELD_MAX) return;   // 满了就丢掉，宁可漏让位也别越界
    petYieldObjs[petYieldCount++] = o;
}

static void petSetBottomYield(bool yield) {
    for (uint8_t i = 0; i < petYieldCount; i++) {
        if (petYieldObjs[i] == nullptr) continue;
        if (yield) lv_obj_add_flag(petYieldObjs[i], LV_OBJ_FLAG_HIDDEN);
        else       lv_obj_clear_flag(petYieldObjs[i], LV_OBJ_FLAG_HIDDEN);
    }
}
```

配套三处小改动（**零布局影响**）：
- `box` 和竖分隔线提升为全局 `hc_bot_box` / `hc_bot_div`，并在
  `resetStylePointers()`（`1418` 那一带）置 nullptr
- 壁纸的 `plate`（`2607`）提升为全局 `wp_plate`，同样在 `resetStylePointers()`
  置 nullptr（`1411` 已有 `wp_lbl_time = nullptr` 那行，照它加）
- `build_style_high_contrast()` / `build_style_wallpaper()` 末尾用
  `petYieldAdd()` 逐个填进清单；**切风格时 `renderCurrentDisplayBase()`
  已经先把旧容器全删了**（`8891-8907`），所以清单必须在每个 build 里
  重新填一遍并把 `petYieldCount` 归零，不能留上一次的野指针

> ✅ `updateDynamicElements()` 在探头期间**照常跑**、照常往这些 hidden 对象写值。
> 这是安全的：`setText`/`setBgColor`/`setSizePos` 内部都先读回比对
> （`1845-1856`），值没变就不写；有变化也只是写进 hidden 对象，LVGL 不画。
> 千万别为了"省事"在探头期间跳过它——`lockStateDirty` 是靠它内部清的
> （`8803-8804`），跳过会退化成每轮 loop 都往 C3 推 61 字节灯帧、
> 6 秒后看门狗判定卡死重启（`9680-9690` 整段注释在讲这个）。

## 5. 宠物状态：纯数据 + 姿态

跟 LVGL 解耦，只描述"它是谁、它什么心情"：

```c
enum PetPose { POSE_IDLE, POSE_GREET, POSE_HAPPY, POSE_HUNGRY,
               POSE_SLEEP, POSE_ANGRY, POSE_SICK };   // 7 个姿态

struct PetState {
  uint8_t  mood;          // 心情 0..100，驱动顶栏条
  uint16_t bond;          // 亲密度，长期累积，决定台词口吻
  uint8_t  pose;          // 当前姿态
  uint32_t poseUntilMs;   // 姿态何时自然结束（自动回 IDLE）
  uint32_t lastPettedMs;  // 上次被摸
  uint32_t lastSeenMs;    // 上次见到人（算"你走了多久"）
  uint8_t  fedToday;      // 今日喂食次数
  uint32_t fedYmd;        // 今日喂食 YYYYMMDD（跨日清零照抄 5864-5881）
  uint8_t  peekToday;     // 今日探头次数（对 8 的上限）
  uint8_t  bothered;      // 连续被打扰次数，>=2 暂停 24h
};
```

**关键约束：姿态是"到点自动结束"的，不是外部 tick 驱动的。**
这样"没人碰它"时零 LVGL 写入——照抄 `tickRhythm()`（`8823-8859`）的范式：
`millis()` 自节流 + 状态数组 + 空闲早退。那 24 根柱子静止时一次 LVGL 调用都没有，
是全项目性能做得最干净的一处，宠物照这个来。`petGate()` 同理，
返回 `SCENE_NONE` 时**一次 LVGL 调用都不该有**。

### 事件接线表

| 事件 | 钩子位置 | 宠物反应 |
| --- | --- | --- |
| **静音键** | `BTN:MUTE`（`8285`） | 摸头：`mood+2, bond+1`，冷却 800ms 防连点 |
| **旋钮转** | `ENC:+/−`（`8235-8237`） | 撸猫：连续输入 = 一直摸，转得越快越开心（最适合"撸"的手感） |
| **旋钮按下** | `BTN:KNOB`（`8239`） | 喂食：`mood+15, fedToday+1` |
| **长按灯光键** | `BTN:LIGHT_HOLD`（`8266`） | 退出宠物页 / 收起探头 |
| **矩阵键按下** | `5886`（`triggerKeyReaction()` 旁边） | 你在打字 → 它在"听"，偶尔探头评论。**不吞键** |
| 闲置 > 3 分钟 | `millis() - lastActivityTime` | 换 `POSE_SLEEP`，台词转"你还在吗…" |
| 回来（上次是睡眠态） | 同上，转正时算差值 | `POSE_GREET`，报出走时长 |
| KPM 骤增 | `kpmRing`（`610`） | 偶尔探头："你在赶稿吗"（带 30min 冷却） |
| 今日击键过千 | `todayKeyCount`（`616`） | 跨日第一次：报今天数字 |
| 温度 > 28℃ | SHT31 曲线 | `POSE_SICK`："好热，趴着不动了" |
| 温度 < 15℃ | 同上 | 蜷成一团 |
| 到饭点（`localtime`） | 无需硬件 | `POSE_HUNGRY` |
| 闹钟/倒计时响铃 | `startRinging()`（`3756`） | 被吵醒，情绪掉（**响铃优先级最高，宠物不抢它的版面**） |

> ⚠️ 没有 WiFi / NTP，时间只靠 BLE `TIME:` 下发（`7249`），
> 掉电又不连蓝牙的话时钟会停在掉电那一刻。所以**时段问候（早/午/晚安）
> 要能接受"时间不准"**——不要写成精确到分钟的场景。

## 6. 键位：全部走 C3 实体键，矩阵键一个都不占

用户的判断是对的，而且比"换个退出键"更要紧：**矩阵键全都要用来打字。**
拿 ESC / 空格 / 回车做宠物操作，等于为了逗猫牺牲正常输入。

而这台键盘上**恰好有三个不参与打字的键**——静音键、灯光键、灯效键物理上挂在
C3 小 MCU 上，走 Serial1 上报，**矩阵里根本没有这一格**（README:122-123）。
全屏宠物页的每一个操作都用它们，矩阵键一律照常发给主机。

### 键位表

| 键 | C3 命令 | 宠物页行为 | 原有行为 |
| --- | --- | --- | --- |
| **旋钮转** | `ENC:+` / `ENC:-` / `ROT:R/L`（`8235-8237`） | 撸猫，连续转 = 一直摸 | **照常**调背光/亮度（借道） |
| **旋钮按下** | `BTN:KNOB`（`8239`） | 喂食 `mood+15, fedToday+1` | **照常**打一下律动（借道） |
| **静音键** | `BTN:MUTE`（`8285`） | 摸头 `mood+2, bond+1` | **照常**发静音给主机（借道） |
| **灯光键长按** | `BTN:LIGHT_HOLD`（`8266`） | **退出宠物页** | 倒计时全屏不在时是切背光，宠物页时无冲突 |
| 灯光键短按 | `BTN:LIGHT`（`8250`） | — | 照常切控制目标 |
| 灯效键 | `BTN:CPG`（`8303`） | — | 照常切灯效 |
| **灯效键长按 / 静音键长按** | `BTN:CPG_HOLD` / `BTN:MUTE_HOLD`（`8313`） | — | ⚠️ **这两个是"进下载模式重启"，绝不碰** |
| **全部矩阵键** | — | — | **照常发给主机，宠物页一个都不吞** |

底部提示行只有一行（`mkHintLine` 那套，216px 内）：
`静音摸 · 旋钮撸 · 灯长退`（实测 168px）。

### "借道不吞键"是现成的设计原则

`8285-8301` 处理静音键时已经写明了理由：

> 静音本身照常发给主机 —— 响铃期间用户很可能正在放声音，
> 把静音也吞掉反而是帮倒忙。**所以只停铃，不 return。**

宠物页完全沿用：摸猫的时候手正好按到静音键，它喵一声，
同时你的电脑静音了——**不违背直觉，也不破坏原语义**。
旋钮转它照样在调背光亮度，只是同时被撸了。

### `SYS_MODE_PET` 绝对不能进 `inUiMode`

这是整个设计里最容易踩、后果最严重的一条。`5899-5907`：

```c
const bool inUiMode = (currentSysMode == SYS_MODE_MENU)
                      || IS_SETTING_MODE(currentSysMode)
                      || inRecMode || inElogMode;
if (inUiMode) {
    // ---- 界面态：这一整块把按键吃干净，一律不发到主机 ----
```

**只要把 `SYS_MODE_PET` 加进这个表达式，宠物页就会吞掉所有矩阵键**，
你在猫旁边一个字都打不出来。反过来——**什么都不加**，宠物页里的矩阵键
自然走下面 `6055-6080` 的普通键盘分支发给主机，而且宠物会因为你在打字
而做出反应（`pulseRhythm()` 已经是这个套路）。

宠物页在 `handleC3Command()` 里的接管点放在**最前面**（在 `8233` 的
`if (currentSysMode == SYS_MODE_SLEEP)` 之后），这样所有 C3 输入
先经过宠物，其余语义原样落回下面的分支。

### 探头横条：矩阵键照常，只把 LOGO 收掉

探头是 8 秒的临时浮层，**更不能吞键**（用户正在打字时它凑过来说话，
把键吞了就打字卡壳）。所以探头在场时只有 LOGO 被特殊对待：

| 键 | 平时 | 探头在场时 |
| --- | --- | --- |
| LOGO 短按 | 切主屏风格 | **吞掉**（你想关它却切了风格会很气） |
| LOGO 长按 | 进宠物页 | 收起探头 + 记一次被打扰 |
| 静音 / 旋钮 | 各自原义 | **照常 + 额外算一次"被摸"**（`bothered--`） |
| 其它矩阵键 | 发给主机 | **照常发给主机** |

### 长按 LOGO：矩阵键的长按检测要新写

LOGO 键现在的全部逻辑就 8 行（`6017-6024`）：

```c
else if (baseKey == K_LOGO) {
    // LOGO 短按 = 切换主屏风格；Fn+LOGO 仍然保留重启
    if (fnPressed) {
        triggerHud("系统重启", "请稍候", lv_color_hex(CLR_RED));
        pendingRestartMs = millis() + 600;
    } else {
        cycleDisplayStyle();
    }
}
```

**三个必须注意的事实：**

1. **矩阵键没有长按检测。** 全工程 `_HOLD` 只有 `BTN:LIGHT_HOLD`（`8266`）、
   `BTN:MUTE_HOLD` / `BTN:CPG_HOLD`（`8313`）——全是从 C3 小 MCU 经 Serial1
   上报的事件。矩阵这条路只有"按下/松开"两态（`keebMatrix` + `hostKeyHeld`，
   `517`/`521`），长按检测要新写。
2. **短按现在是"按下即执行"**（`6017` 在按下的 `if (currentState)` 分支里）。
   要区分长短按，必须改成**松手时判定**，否则长按会先把风格切了。
3. **Fn+LOGO 是重启**（`pendingRestartMs`），不能被长按抢走。
   判据用 `fnPressed`：Fn 按住 → 永远走重启分支，不进长按逻辑。

```c
#define LOGO_HOLD_MS 600UL      // ≥600ms 算长按
static uint32_t logoDownMs    = 0;
static bool     logoHoldFired = false;

// 按下：只记时刻，不执行
logoDownMs = millis(); logoHoldFired = false;

// 扫描节拍（8ms，SCAN_INTERVAL）里，只要还是按住状态：
if (!fnPressed && !logoHoldFired && millis() - logoDownMs >= LOGO_HOLD_MS) {
    logoHoldFired = true;
    if (petScene == SCENE_FULL) petExitFull();            // 宠物页：退出
    else if (petScene == SCENE_PEEK) petDismiss("长按关闭"); // 探头：收起
    else petEnterFull();                                  // 平时：进宠物页
}

// 松手：没触发过长按才算短按
if (!logoHoldFired) {
    if (fnPressed) { /* 原重启分支 */ }
    else if (petScene == SCENE_FULL)  petExitFull();       // 页内短按也退出
    else if (petScene == SCENE_PEEK)  { /* 吞掉：不切风格 */ }
    else cycleDisplayStyle();
}
```

> 宠物页在场时不需要区分长短按——两个都是退出。在"看不见主屏"的页面里
> 按 LOGO 切主屏风格是毫无意义的动作，用户的直觉是"我要出去"。

> ⚠️ 长按之后松手**不能**再发一个孤立的 `hostKeyHeld` 配对 release，
> 也不要把长按误判成一次宏/组合键执行。`hostKeyHeld` 的配对逻辑在
> `6095-6102`，改的时候两处一起看。

## 7. 台词系统

```c
struct PetLine { uint8_t moodMin, moodMax; uint8_t pose; const char* text; };
static const PetLine petLines[] = { ... };   // 编译进 flash，60~100 条 ≈ 6KB
```

- 挑句：按当前 mood 区间 + 姿态过滤，`esp_random()` 抽（`8865` 已有先例）
- **冷却是硬要求**：全局 8s，同一分类 60s。否则宠物会变成噪音
- 两行拆分规则固定：写死每行 ≤ 13 字，**不要做自动换行**——
  `LV_LABEL_LONG_WRAP` 在 16px 字体上会把标点甩到行首，很难看
- 台词全部用常用字。字库 cmap 覆盖 `0xB0` 起的三段连续区段、一直到 `0xFCE7`
  （≈ 全部常用汉字），日常口语**零字库成本**。真要加生僻字才需要重跑 `gen_font.py`，
  而那个脚本第 32 行写死了 `C:\Windows\Fonts\simhei.ttf`，在这台 Mac 上跑不了
  （可替代：`/System/Library/Fonts/STHeiti Medium.ttc`，字形风格略有差别）

## 8. 对外：手机能跟它说话

协议已经有的：`NOTIFY:<text>`（`8093`）和 `ALERT:<色>[:正文]`（`8100`）——
**"从手机给键盘发一句话"这条路本来就是通的**，网页上已有
`sendAlertWithText()`（`s3-setting.html:2907`）。宠物直接复用。

新增四个 verb，都在 `handleCommand()` 里（回调跑在主任务，可以直接碰 LVGL）：

| verb | 作用 |
| --- | --- |
| `PETMSG:<text>` | 宠物"转述"手机来的话：`"你手机说：记得喝水"` |
| `PETFEED` | 远程投喂，`bond+1` |
| `PETDUMP` | 回 `PETDUMP`：mood/bond/fedToday/上次互动时间 |
| `PETNAME:<text>` | 改名（写 NVS `pet_name`，≤ 8 字节） |

⚠️ `SET:` 会自动给键名加方案号前缀（`7616-7623`），**所以宠物状态一律走
`GSET:`（→ `g_<NAME>`）或直接 `preferences` 写**，别用 `SET:`。

### NVS 新 key（全是新名字，不与现有 21 个 key 冲突）

```
pet_name    String  宠物名，默认 "小橘"
pet_mood    UChar   心情快照（防止关机后归零）
pet_bond    UInt    亲密度
pet_fed_n   UChar   今日喂食次数
pet_fed_y   UInt    今日喂食 YYYYMMDD
pet_seen    ULong   上次互动时间戳
pet_peek_on Bool   主动探头总开关，**默认 true**
pet_from_h  UChar   显示时段起（小时 0..23），默认 23
pet_to_h    UChar   显示时段止（小时 0..23），默认 7
pet_peek_n  UChar   今日探头次数（对 8 的上限）
pet_peek_y  UInt    今日探头 YYYYMMDD
pet_bother  UChar   连续被打扰次数（>=2 暂停 24h）
pet_mute_y  UInt    主动探头暂停到哪一天 YYYYMMDD
```

`pet_peek_on` 默认 `true` 用 `getBool("pet_peek_on", true)` 写——
`Preferences::getBool` 的第二个参数是**键不存在时的返回值**，
传 `false` 就等于默认关，与需求相反。

> 日期型 key（`pet_fed_y` / `pet_peek_y` / `pet_mute_y`）统一用 `localtime()` 的
> `tm_year*10000 + tm_mon*100 + tm_mday` 组 YYYYMMDD，判跨日复用
> `todayDateYmd` 那套（`5864-5881`）。别用 `time()` 直接比时间戳——
> 掉电不复位时（无 NTP）时间戳可能是 1970 或某个冻结的旧值。

### 菜单结构

宠物是一个**新的一级组**（现有 6 组：`显示/灯光/时间/键盘/温湿度/系统`，
`707` 的 `menuGroups[]`）。**追加在末尾**，理由和 `SAVER_PET` 一样：
`runMenuAction()` 走 `MenuAction` 枚举而不是数组下标（README:223-224），
但 NVS 里 `pet_*` 这些 key 名不能因为重排而换位置。

```
宠物
├── 主动打招呼   开 / 关          （pet_peek_on）
├── 显示时段     23:00 – 07:00   （pet_from_h / pet_to_h，小时粒度）
├── 摸一摸       立刻 +mood（等价于进页后按空格，给个"我在这"的入口）
├── 改名字       ≤8 字节
└── 清空亲密度   bond=0, mood=50
```

时段那项的交互：`←→` 调起始小时、`↑↓` 调结束小时？不对——
沿用灯光设置页那种"一行一个字段"的排法更省事：
一行显示 `23:00-07:00`，`←→` 改起、`↑↓` 改止，底部提示写清楚。

## 11. 设计已收口，剩下的是上板试出来的东西

所有结构性问题都已经定了。真正要等**烧进去用一段时间**才知道的：

1. **旋钮撸猫的手感**：`ENC:+/−` 是不是每转一格都算一次摸？
   旋钮的档位密度够不够"连续撸"的手感，还是要做成"转速越快越开心"？
2. **静音键当摸头的手感对不对**：用户按它本来是想静音，
   顺带摸一下猫。这个"一键两用"会不会让人觉得别扭？
3. **探头开场的两句话**选哪两句（"说明型"教怎么关 / "卖萌型"只卖萌）。
4. **8 秒**到底够不够看——特别是台词两行 + 一行键位提示的情况下。
