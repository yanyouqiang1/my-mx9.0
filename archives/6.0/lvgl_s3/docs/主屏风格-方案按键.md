## 1. 用户要的布局

240×240 的屏，整个风格就三块：

```
┌────────────────────────────────────┐  y=0
│              YYQ键盘                │  顶部一行字
├────────────────────────────────────┤  y=28
│  ╭─────╮   ┌──────────────────┐   │
│  │  🍎  │   │                  │   │
│  │      │   │      Space       │   │  按键名（主体，字号自适应）
│  │  🪟  │   │                  │   │
│  ╰─────╯   │           1284   │   │  右下角：今日按键数
│   方案      └──────────────────┘   │
├────────────────────────────────────┤  y=204
│ 温度 ▓▓▓▓▓░░░░░░  23.5°C            │  两条窄条
│ 湿度 ▓▓▓▓▓▓▓░░░░   48%             │
└────────────────────────────────────┘  y=240
```

- **顶部**：一行字 `YYQ键盘`。这行取代了现有的 `dashTopBar()` 顶栏
  （不再有 NUM/CAPS/SCR 三颗锁灯和方案序号）。
- **左侧**：方案。两个图标 —— 白色咬一口苹果 = macOS 方案，
  蓝色 Windows 四格旗 = Windows 方案。当前方案点亮，另一个压灰。
- **右侧大块**：刚按下的键（`lastKeyPressed`），右下角是今日按键总数（`todayKeyCount`）。
- **底部**：温度 / 湿度两条很窄的条。

**重点 = 方案 + 按键**，所以右卡给到 166px（屏宽的 69%），左列只留 62px。

## 3. 素材：图标

### 3.1 为什么不用现成的 `src/profile_icons.h`

那套是 mmx 图像生成出来的位图，48px 档实测：

- 苹果 —— 糊成一坨白团，边缘带粉/绿杂色，**认不出是苹果**；
- Windows —— 是**青绿渐变**，不是用户要的蓝。

### 3.2 新方案：矢量路径栅格化

`gen_style_icons.py` → `src/style_icons.h`

- 素材：Font Awesome Free 6.7.2 `brands/apple` + `brands/windows`
  （图标本体 CC BY 4.0，字体 SIL OFL 1.1；脚本不联网，路径内嵌）
- 做法：SVG path 解析 → 贝塞尔展平 → 8× 超采样 → LANCZOS 缩到 52×52
- 颜色：苹果 `#FFFFFF`，Windows `#0078D4`（官方蓝），未选中态 `#5B6579`
  （= 固件的 `CLR_TEXT_MUTE`）
- 输出格式：`LV_IMG_CF_TRUE_COLOR_ALPHA`，每像素 **3 字节**
  = `[RGB565 高, RGB565 低, alpha]`
  （`LV_COLOR_DEPTH=16` → `LV_IMG_PX_SIZE_ALPHA_BYTE = 3`，
  已对 `.pio/libdeps/.../lvgl/src/draw/lv_img_buf.h`）
- 体积：4 张 × 52×52×3 = **32.4 KB** Flash（当前 Flash 用量 62.8%，加完约 63.8%）

四张图：`style_icon_apple` / `style_icon_apple_dim` / `style_icon_win` / `style_icon_win_dim`。

> 用 alpha 而不是"烤死底色"是有意的：图标要压在 `CLR_SURFACE_2` 的高亮卡片上，
> 底色烤死会露出黑边。

### 3.3 现有 `profile_icons.h` 怎么办

**不动**。新风格用自己的一套 `style_icons.h`，两者互不干扰，
`profile_icons.h` 继续服务老风格的顶栏和高对比度页。

## 5. 字号必须量，不能猜

`lvgl_font_width.py` 直接读 LVGL 字体 `.c` 里的 `adv_w`（真实值 × 16），
得到**屏幕上的真实宽度**。用 PIL 量系统字体是没用的 —— 屏上跑的是自带的 Montserrat。

实测（内宽 158px 时）：

| 键名 | 48px | 28px | 选中 |
|---|---|---|---|
| Space | 148.1 | 86.4 | **48** |
| Home | 149.6 | 87.2 | **48** |
| RIGHT | 154.0 | 89.9 | **48** |
| Num * | 154.4 | 90.1 | **48** |
| NumLk | 180.3 | 105.2 | 28 |
| DOWN | 173.0 | 100.9 | 28 |
| NumEnt | 207.0 | 120.7 | 28 |

> ⚠️ `NumEnt` 在 48px 是 207px，**会撑爆卡片**。所以字号必须按宽度动态选，
> 不能按字符个数拍脑袋定死。
> `lv_conf.h` 里 `LV_FONT_MONTSERRAT_32 = 0`（没开），可选字号只有
> 48 / 28 / 24 / 20 / 18 / 16 / 14 / 12 / 10 / 8。

### 6.3 ⚠️ `resetStylePointers()` —— 必须改

`lvgl_s3.ino:1658`。**这是历史上"切风格就崩"的真凶**：
`lv_obj_del(pk_bg)` 会连带释放所有子控件，但 LVGL 不会替我们把外部指针置空，
下一轮 `updateDynamicElements()` 往野指针上写 → 踩坏堆 → 重启。

所以新风格的**每一个**指针都要在这里置 `nullptr`，一个都不能漏。

### 6.4 `destroyMainScreen()`

`lvgl_s3.ino:1715`，加一行 `pk_bg = nullptr;`（和其它风格一样）。

### 6.5 `renderCurrentDisplayBase()`

`lvgl_s3.ino:10753`，两处：

1. 清理段加 `if (pk_bg) { lv_obj_del(pk_bg); pk_bg = nullptr; }`
2. 末尾的 switch 加 `case DISP_MODE_PLAN_KEY: build_style_plankey(); break;`

### 6.6 `build_style_plankey()` —— 新函数

放在 `build_style_high_contrast()` 后面。照抄 `build_style_keymon()` 的骨架：

- `makeRootPanel(ensureMainScreen(), CLR_BG)` 建底
- **不用 `dashTopBar()`** —— 这页的顶部就是标题行，锁灯不显示
- 左列两个 `lv_img`（`lv_img_set_src` 挂 `style_icon_*_desc`）
- 右卡 `lv_obj_create` + `mkCard(card, CLR_SURFACE, 12)`
- 按键名：`lv_label_create` + 运行时 `lv_obj_set_style_text_font()`
  在 48 / 28 / 24 之间挑放得下的最大档
- 底部两条窄条：轨道 + 填充两个 `lv_obj`，用 `lv_obj_set_width()` 改长度

### 6.7 `updateDynamicElements()`

`lvgl_s3.ino:~10400` 的 switch 加一个 case：

- `setText(pk_lbl_key, lastKeyPressed)`
- `setText(pk_lbl_today, todayKeyCount)` —— 数字用 `snprintf` 进静态 buffer
- 温湿度：`shtAvailable` 为 false 时显示 `--.-°C` / `--%`，
  **条不能拿初值 0 画成满格**（照抄高对比度页的处理）
- 方案图标：见 6.8

### 6.8 方案切换时刷新图标 ⚠️

`switchProfile()`（`lvgl_s3.ino:6002`）现在只调 `updateTopBarProfile()`，
新风格的图标**不在顶栏**，所以要额外加一个 `updatePlanKeyProfile()`：

```c
static void updatePlanKeyProfile(void) {
    if (!pk_img[0] || !pk_img[1]) return;
    bool mac = (currentProfile == 1);
    lv_img_set_src(pk_img[0], mac ? &style_icon_apple_desc : &style_icon_apple_dim_desc);
    lv_img_set_src(pk_img[1], mac ? &style_icon_win_dim_desc : &style_icon_win_desc);
    // 高亮底卡跟着换
    ...
}
```

调用点：`switchProfile()` 末尾 + `updateDynamicElements()` 里兜底。

> 为什么两个都要：`updateDynamicElements()` 开头有"系统时间没校准就 return"的分支，
> 只靠它会出现"换了方案图标不跟着变"。

### 6.9 风格诊断掩码

`STYLE_BIT_*`（`lvgl_s3.ino:1628`）加 `STYLE_BIT_PLAN_KEY`，
并加进 `STYLE_BIT_ALL`。`MAIN_STYLE_MASK` 保持 `STYLE_BIT_ALL` 不变。

## 9. 实施时才发现的三个坑

### 坑 1：「系统时间没校准就 return」的早退会吃掉这一页的核心

`updateDynamicElements()` 开头有：
```c
if (!ti || ti->tm_year < 124) { lockStateDirty = false; return; }
```
这个早退在 `switch (currentDispMode)` **之前**。而这一页显示的
「刚按下的键 / 今日次数 / 温湿度 / 锁灯」**一样都不依赖系统时间** ——
要是按老套路把这一页塞进 switch，没对上 NTP 的时候页面会一直停在初始状态，
**按什么键屏幕都不动**，正好把这一页最核心的东西废掉。

**改法**：把这一页的刷新抽成 `updatePlanKeyElements()`，
在 `updateDynamicElements()` 的早退**之前**单独调用。

### 坑 2：按键名挂错父对象 → 没居中

`lv_obj_align(obj, LV_ALIGN_TOP_MID, ...)` 是相对**父对象**居中的。
按键名一开始挂在 `pk_bg`（240 宽的根面板）上 → 居中到屏幕中线 x=120，
而这张卡的中心在 x=152 —— 差 32px，看着就是"字没居中"。

**改法**：按键名和右下角那两个都挂到 `pk_card` 里，位置自然跟着卡走。

### 坑 3：`lv_img_set_src()` 每 100ms 调一次 = 屏幕永远 dirty

`updateDynamicElements()` 每 100ms 跑一次。如果每次都
`lv_img_set_src()` 换方案图标，等于每 100ms 触发一次 invalidate + 重排版，
SPI 一直在推满屏。

**改法**：加一个 `pkShownProfile` 记着"当前贴的是哪个方案"，
方案没变就直接 return。`resetStylePointers()` 和 `build_style_plankey()` 里
把它重置成不可能值，保证重建时一定重新贴图。

> 其它风格的高对比度页有同样的毛病（每 100ms 无脑 `lv_img_set_src`），
> 属于既有行为，这次没顺手改 —— 改它要连带验证那条链路的刷新率。
