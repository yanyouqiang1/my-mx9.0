# LVGL 核心版固件 (lvgl_s3)

基于 ESP32-S3-N16R8 + ST7789 240x240 + LVGL 8.4.x

## 风格：简约纯黑

- 深黑背景 #000000
- 白色/青色数字文字
- 顶部 NUM/CAPS/SCROLL LED 状态
- 中央大号时钟 (Montserrat 48)
- 日期 + 温湿度 + 击键统计

## 功能（核心优先）

1. **键盘矩阵** - 10x16 完整扫描
2. **USB HID** - 键盘输入 + 媒体键
3. **时间显示** - 时钟 + 日期
4. **温湿度** - SHT31 传感器
5. **简化菜单** - 切换显示模式
6. **HUD 通知** - 操作反馈

## 显示模式

1. **极客仪表盘** - 时间/温湿度/击键
2. **大字时钟** - 简约大号时间

## 硬件

- ESP32-S3-N16R8
- ST7789 240x240 LCD
- MCP23017 键盘矩阵
- SHT31 温湿度传感器
- WS2812 LED (19颗)

## 烧录

```bash
pio run -t upload
```

## 改完界面文案后必须重生成字体

界面里的中文是靠 `src/lv_font_simsun_16_cjk.c` 这个子集字库渲染的。
**在 .ino 里新增/修改任何中文后，要重跑一次字体生成**，否则新字会是空白：

```bash
python gen_font.py    # 重新生成 lv_font_simsun_16_cjk.c + charset.txt
python check_font.py  # 确认 MISSING 为 0
```

`gen_font.py` 会扫 .ino 里的字符串字面量 + 一份兜底词表，用 `C:\Windows\Fonts\simhei.ttf`
生成 16px / bpp=4 的子集，并挂上 `fallback = &lv_font_montserrat_14`。

> ⚠️ 别把参数改回 `--symbol charset.txt`。这版 lv_font_conv 的 `--symbols`
> **不读文件**，参数值会被当成字面字符（见 `node_modules/lv_font_conv/lib/collect_font_data.js`），
> 结果就是字库里一个汉字都没有、界面全是豆腐块。脚本改成传 `-r` 码点区间（纯 ASCII，
> 不会被 Windows 的 cmd + GBK 代码页改写）。

字体相关约定：

- `LV_FONT_DEFAULT` 指向中文字体 → 凡是没显式指定字体的控件都能出中文
- 需要显示中文的 label 显式用 `&lv_font_simsun_16_cjk`（方案名 / HUD / 通知条）
- 纯英文数字的控件继续用 `lv_font_montserrat_*`，观感更好

## 屏幕与按键的约定

- 主屏是真正的 `lv_obj_t` 屏幕对象，由 `ensureMainScreen()` 建/取，
  6 种主屏风格都建在它上面。**不要**改回 `lv_obj_create(lv_scr_act())`。
- 6 种风格的根容器统一用 `makeRootPanel()` 建，**不要**再手写 `lv_obj_create` +
  `set_size/pos`。原因：LVGL 默认主题给普通 `lv_obj` 套了 `card` 样式（`pad_all = 13px`
  @DPI130），而 `lv_obj_set_pos()` 会走 `lv_obj_move_to()`，**把父对象的 pad+border
  叠进子对象坐标**。于是任何"贴在 (0,0)"的子对象都会右下偏 13px，右边和下边被裁掉
  —— 表现就是"整个界面往右移了一点"、壁纸模式下尤其明显。用 `lv_obj_align()` 的
  子对象不受影响（对齐算 content 区中心，pad 对称时中心不变），所以很容易漏。
- 顶部条（`dashTopBar()`）左三是三颗锁状态灯（NUM/CAP/SCR，只画圆点不写文字，
  外面套一圈同色细环，亮起时才显形），右边是方案指示：序号常显，1/2 号方案另配
  系统图标（Windows 四格窗 / 苹果），图标全部用 `lv_obj` 基本图形拼，改样式时
  别去动 `topIconWin[] / topIconMac[]` 的创建顺序（= 绘制顺序：果体 → 缺口 → 果柄 → 叶）。
- 三颗锁状态**翻转的那一刻**会弹一条 HUD（`updateDynamicElements` 里用
  `lockPrev[]` 比对上一帧）。顶栏那三颗灯太靠边，离远了看不出大写开没开，
  光靠变色不够。`lockPrevValid` 是"界面刚重建"的标志：重建后第一帧只记录不弹窗，
  否则每次回主屏都会一口气弹三条。
- **Montserrat 里没有汉字，也没有到中文字库的回退**（回退是单向的：
  `lv_font_simsun_16_cjk.fallback = &lv_font_montserrat_14`，反过来没有）。
  挂 `lv_font_montserrat_*` 的 label 写中文 = 一片空白。要显示中文就显式换
  `&lv_font_simsun_16_cjk`；纯 ASCII 的占位符（`--`）才可以用 Montserrat。
- 日期统一走 `formatDateCN()`（"9月27日 星期六"）。用了它的 label 必须是中文字库。
- **别用 `transform_zoom` / `transform_angle` 放大字号或做视觉效果**：
  LVGL 8.4 的软件渲染器对需要 alpha 的中间图层有一道闸门
  （`lv_draw_sw_layer.c`: `LV_COLOR_SCREEN_TRANSP == 0 && HAS_ALPHA → return NULL`），
  本项目没开 `LV_COLOR_SCREEN_TRANSP`，走这条路的控件会被**静默地整个不画**。
  要大字就上大字号的字库。
- 回主屏统一走 `gotoMainScreen()`，它负责模式复位 + 内容重建 + 切屏。
- 按键分发顺序必须和 `s3/s3.ino` 原版一致：界面态（菜单 → 设置 → 录制）先接管，
  `K_MC` 放最后。在界面态里 `K_MC` 和 `ESC` 都是"退出"。
- 宏/序列/组合键的执行链和原版 `s3/s3.ino` 一致：`executeGlobalKey()` 吃
  `GSET` 的 `SW:x+SEQ:…` / `SW:x+CMB:…`，`executeMacro()` 吃按方案的
  `p<n>_<键名>`（`SEQ:` / `CMB:` 两种）。网页端 `s3-setting.html` 发的
  `SET:p0_M1:…` 名字里已经带方案号，固件端**不要再拼一层** `p<currentProfile>_`。
- 按键编码只有**一套**在矩阵里用：Arduino 的 "0x88 + HID usage"。
  0xE0~0xE7 在这里是**小键盘回车 / 小键盘 1~7**（0x88+0x58=0xE0=NumEnt，
  0x88+0x5F=0xE7=Num 7），**不是**修饰键 —— 别在 kbPress 里把它们当 0xE0~0xE7
  的 HID 修饰键处理，一处理整片小键盘就全错（7 会变成 Win 键）。
  网页"按键映射"下拉里那几个 "🔹 Left Ctrl"=224 才是 HID 风格，它们的换算
  统一在 `normalizeRemapKey()` 里做，只作用于 remap 表的读入/读出。
- **小键盘符号键（`/ * - +`）必须用 `0xDC~0xDF`，不能退回 ASCII**。
  这里踩过两次，两个方向的错都犯过：
  · 用 HID usage `0x53~0x63` → 和 ASCII `'a'/'b'/'c'`(0x61~0x63) 数值撞车，
    基础键盘按 A/B/C 会发成 Num 9 / Num 0 / Num .（见提交 `9973f87` 的 A→9 修复）。
  · 改用 ASCII 规避撞车 → `*`=42 走 `_asciimap` 变成**主键盘 Shift+8**、
    `+`=43 变成 Shift+=，发出来的压根不是小键盘那颗键（Mac 上数字小键盘就是废的）。
  正解是 `0x88 + HID usage`：`Num /`=0xDC `Num *`=0xDD `Num -`=0xDE `Num +`=0xDF。
  这一串既和 a/b/c 不撞车，又和网页"🔹 修饰键"224~231 不撞车，走 `kbPress` 的
  `>=0x88` 分支被减回 `0x54~0x57` 交给 `pressRaw`，发出的是**真正的小键盘键**。
  效果上等于"宏里选 Num \*"和"手按物理小键盘的 \*"发同一个码点。
  小键盘数字（1-9/0/`.`）仍用 ASCII —— `_asciimap` 翻成主键盘数字，字符是对的；
  换成 `0xE0~0xE7` 反而会被 `normalizeRemapKey()` 当修饰键折算掉。
  ⚠ 网页 `s3-setting.html` 的 `KEY_OPTIONS` 是同一套值的另一个副本，**改一处要改两处**。
- 同一个坑的第二个面：**别拿 Consumer 页的 usage 去比 `baseKey`**。
  0xE2 = 0x88+0x5A = **小键盘 2**，不是静音 —— 谁在按键分发里写
  `else if (baseKey == 0xE2)` 做 Mute，小键盘 2 就会静音且不再当数字键用。
  静音键物理上挂在小 MCU **C3** 上，走 Serial1 的 `BTN:MUTE`
  （`handleC3Command`），**矩阵里没有这一格**，不要试图在矩阵里加。

## 闹钟 / 倒计时

两个功能共用一套**响铃引擎**（`ringingKind` / `startRinging()` / `stopRinging()` /
`drawRingOverlay()`）：到点了就是"响铃"这个状态，主背光整排黄灯快闪 + 屏幕上
一张常驻卡片，只有文案和中间那个大数字不同。

### 响铃时长 / 怎么停

- 停铃键**只有两个**：灯光键、静音键（用户定的）。其它键照常发给主机，
  响铃期间打字不受影响。
- 响铃期间**不能息屏**：`loop()` 的息屏判断会放过 `ringingKind != RING_NONE`，
  屏幕一黑就等于没提醒。起铃时 `startRinging()` 还会把 `lastActivityTime`
  拨到当下、把屏叫醒。
- 60 秒没人理会自动停铃，但会往通知队列塞一条"闹钟未确认"/"倒计时未确认"，
  不静默丢失（`RING_SAFETY_MS`）。没有这道兜底，一排黄灯能闪一整晚。
- 响铃的优先级**高于通知告警**（`renderLightingEngine()` 里响铃分支排在
  `currentAlertType()` 之前）：通知是主机推的消息，响铃是"现在不动手就来不及"。
  反过来的话会出现屏上写着"闹钟响了"、灯却在闪红的各说各话。
- 响铃期间 `sendLedFrameToC3()` 强制 `ledScale = 255`：用户可能平时把亮度调到
  很低（夜里用），按那个比例缩下去闪灯就几乎看不见了。

### 倒计时全屏

用户要求：「全屏幕就是展示这一个倒计时，文字很大」。所以倒计时跑起来时是一块
**独立屏幕**（`scr_countdown`），240x240 全部让给那一个 48 号数字，连进度条和
"按灯光键退出"都不加 —— 加了它就变成另一块主屏，那就不是用户要的东西。

- 字号：48 号 Montserrat 里数字 28~32px、冒号约 11px，最坏情况 `88:88:88`
  ≈ 203px，240px 的屏放得下。不满 1 小时只排 `MM:SS`（约 142px）。
- **按住灯光键退出全屏，倒计时继续在后台跑**（`BTN:LIGHT_HOLD`）。收走屏
  不等于取消计时；跑完照样响铃。这一路长按不会再顺手切背光总开关，
  否则"退出全屏"会把用户的灯关掉、还得再按一次才开得回来。
- 让位规则集中在 `updateCountdownVisibility()`，不要在各个调用点自己
  `showScreen()`：进菜单/设置页/录制/日志要让位，响铃中要让位，息屏要让位。
  分散判断迟早漏一处，表现就是"进了菜单底下还是倒计时"。
- 设置页那颗**开始/停止按钮原来是个摆设**：画出来了、文案会跟着
  `timerRunning` 变，但全工程没有任何一行代码处理它，回车键走的是通用保存
  分支，只把时长记进 `timerTotalSec` 就退出，一次都没起过表。现在回车键走
  `toggleCountdownFromKeyboard()`，让按钮说的话成真。

### `TIMERSET:` / `ALARMSET:` 的写法

`TIMERSET:` **三种写法都收**：

| 写法 | 例子 | 谁在发 |
| --- | --- | --- |
| 纯秒数 | `TIMERSET:300` | `s3-setting.html` / `kbctl.py` / `kbctl_hid.py` |
| `MM:SS` | `TIMERSET:05:00` | 手写脚本 |
| `HH:MM:SS` | `TIMERSET:01:05:00` | 手写脚本 |
| 停止 | `TIMERSET:STOP` / `OFF` / `CANCEL` | 网页停止按钮 |

⚠ 以前这里**只认 `HH:MM:SS`**（要求两个冒号），而**所有**远端客户端发的
都是纯秒数 `"TIMERSET:300"`，走不进分支被静默跳过 —— 网页点"启动"只弹了个
`alert`，键盘上什么也没发生。老版 `s3/s3.ino` 三种都收，移植到 LVGL 时这段
容错被漏掉了。

`ALARMSET:` 收 `HH:MM` 和 `OFF`/`0`/`DISABLE`/`CANCEL`。`kbctl.py` 关闹钟发的
是 `ALARMSET:OFF`，以前"OFF"里没有 `:` 走不进分支，**关不掉闹钟而且不报错**。
越界的时/分（`99:99`）现在会被拒掉并提示，不再截断存进 `uint8_t` 等第二天。

### 判定在哪跑

`updateTimers()`，在 `loop()` 里按整秒节流（不占任何中断）：

- **闹钟**：只在"当前这一分钟"命中，再用 `tm_yday` 去重保证一天只响一次
  （不加 yday 会连着响一整分钟）。`tm_year <= 124`（时间没校准）时不判定，
  否则开机瞬间正好撞上 `00:00` 的闹钟会莫名其妙响一次。
  这正是以前"设了闹钟不响"的根因：`alarmLastFiredYday` 声明了却一次都没被读过。
- **倒计时**：剩余量从 `millis() - timerStartMs` **反算**，不是每秒自减 ——
  中间被宏的 `delay()` 或壁纸解码阻塞几百毫秒也不会越欠越多。
  同样是以前只赋值、从没被减过。

## 灯效

- 灯光设置页五个字段：背光开关 / 背光亮度 / 灯效 / 状态灯亮度 / **按键灯效**。
- 按键灯效（`keyFxStyle`，存 NVS `key_fx`）是**叠加层**：按下任意键时
  `triggerKeyReaction()` 置状态，`renderLightingEngine()` 每帧把 0~15 主背光
  先压暗到 ~40%（原版 `updateKeyReaction()` 的 `*102>>8`），再把特效那几颗点亮。
  涟漪=从正中向两侧扩散 / 发射=从末位往回扫子弹 / 堆叠=从末位往回填。
  颜色每按一次自动换一种（原版"自动"档的配色）。
- 叠加层必须写在基础灯效**之后**，顺序反了会被灯效盖掉；告警期间整段不走
  （`renderLightingEngine()` 在告警分支就 return 了），16~18 锁状态灯也不受影响。
- 主背光一共 **16 颗（0~15）**，16/17/18 是三颗锁状态灯。别再把 `0~15` 写成
  写死的 `15`（`i < 15`）—— 那样第 16 颗主灯在常亮灯效下永远是黑的。

## 系统菜单（两级）

一级只列 6 个大类，回车进去才看到该组的具体项：

| 一级 | 二级 |
| --- | --- |
| 显示 | 切换主屏风格 / 切换屏保风格 |
| 灯光 | 灯光设置 |
| 时间 | 设置时间 / 闹钟设置 / 倒计时 |
| 键盘 | 切换配置方案 |
| 温湿度 | 刷新温湿度 / 温度校准 |
| 系统 | 计数清零 / 错误日志 |

- 菜单项要执行什么走 `MenuAction` 枚举 + `runMenuAction()`，**不要按数组下标
  switch** —— 一旦分组重排，下标就全变了。
- `menuSel` 是一级大类下标，`menuItemSel` 是组内项下标，`menuInSub` 决定当前
  在哪一级。ESC 在二级是"回一级"、在一级才是"退出菜单"。
- 列表按 `MENU_ROW_MAX` 建满行、切换层级只改可见性和文字，不整屏删建
  （LVGL 8.4 删活动屏会把 `disp->act_scr` 置 NULL）。
- 已删除的"按键回显开关"：那个 `showKeystrokes` 是纯内存变量、**不落 NVS**，
  每次开机都被初始化回 true，用户关掉、插电或重启一次就自己弹回来。
  而它唯一的用途就是让主屏上那颗"最后按下的键"显示 `--`，没有实际价值。

## 底部按键提示（务必先量宽度）

屏只有 240px 宽，提示行是 16px 中文字体。`adv_w` 在 LVGL 里是 **1/16 px 单位**，
实际像素 = `adv_w / 16`；汉字 16px、ASCII 8px、`·` 8px、方向箭头 **也是 16px**。

原来那些一整行的提示实际有多宽（用 `text_width.py` 量）：

| 文案 | 宽度 | 屏宽 240 |
| --- | --- | --- |
| `←→ 切换 · ↑↓ 调整 · 回车保存 · ESC 取消` | 368px | 溢出 128px |
| `←→ 切换 · ↑↓ 调整 · 回车开始/停止 · ESC 取消` | 408px | 溢出 168px |
| `↑↓ 翻看 · DEL 清空 · ESC 返回` | 264px | 溢出 24px |
| `上下选择 · 回车确认 · ESC 返回` | 256px | 溢出 16px |

居中对齐后左右各裁掉一半，用户看到的就是"底部的字跑出屏幕"。

- 字库是 Windows `simhei.ttf` 生成的 16px 固定字号，**重生成小一号中文字库需要
  Windows 字体源**，开发机上做不了。所以只能拆行 + 砍字。
- 现在统一走 `mkHintLine()` 造**两行**（`HINT_LINE1_Y` / `HINT_LINE2_Y`），
  这是唯一能一条按键说明都不丢的办法 —— ESC 是设置页唯一的"不保存退出"路径，
  压成一行就得砍掉它。
- 每个提示 label 都带 `lv_obj_set_width(HINT_W)` + `LV_LABEL_LONG_DOT`，
  这是硬兜底：以后谁加了超宽文案，超出部分只会变省略号，不会画到屏幕外。
- 加新文案前先跑 `python text_width.py "你的文案"`，超 216px 就是放不下。

## 息屏 / 屏保

- 「显示 → 切换屏保风格」在 黑屏 → 壁纸轮播 → 信息面板 → 关闭 之间循环
  （存 NVS `saver_mode`）。
- **"关闭"这一档不建屏保屏**：空闲到时什么也不做，主屏一直留着
  （`loop()` 的超时判定里 `saverMode != SAVER_OFF` 直接短路）。这也是默认值。
- 档位编号是 NVS 持久化的，**只能往后追加、不能往前插**：原来的
  `SAVER_OFF = 0` 语义是"黑屏"，那个语义现在归 `SAVER_BLACK`。
  把"关闭"插成 0 的话，老用户开机就变成屏保关着，属于静默改设置，
  所以 `SAVER_OFF = 3` 追加在末尾，0/1/2 三个旧值的含义一字不变。
- **壁纸轮播**：壁纸铺满 + 每 5 秒翻出信息面板。信息面板（时间/日期/温湿度）
  全在 `sv_panel` 一块卡里 —— 旧版是四个 label 散在屏幕各处，配上壁纸就是
  四处压图。没上传过壁纸时没有可轮播的图，直接常显面板。
- 进屏保先给图片（`updateScreensaver(true)` 里 `tick = 0` + 藏面板），
  用户最想先看到的是图。轮播计时用 tick 计数而不是时间戳：这个函数既被
  100ms 的节拍调、也被 `enterScreensaver()` 直接调一次，时间戳会被那次调用搅乱。
- 壁纸主屏（风格 6）的时钟在**右下角**一小块（112x40 / 28px 字），
  遮罩是 `LV_OPA_25`。原来 168x64 的板子杵在正中、48px 字，图基本没法看。

## 文件系统与分区（别踩）

- 壁纸 `/logo.bin` 和 ME 文本 `/me_hex.txt` 存在 **SPIFFS** 上，**不是 FFat**。
- 板子默认分区表（PlatformIO 的 `default_8MB.csv` / Arduino IDE 的 `default.csv`）
  里只有 `spiffs` 分区，**没有 ffat 分区**。`FFat.begin()` 找不到 subtype=fat 的分区
  会直接返回 false，之后每次 `FFat.open()` 都是一个无效 File —— 表现就是
  "ME 文本存入失败""壁纸重启就丢"。
- 所以烧录时的分区方案必须是**默认那几档**（带 spiffs 的）；选了
  "16MB Flash (3MB APP/9.9MB FATFS)" 这类 FATFS 方案，SPIFFS 反而会挂不上。
  （`lvgl_demo/` 那个 README 让人选 FATFS，是历史遗留，别照做。）
- 分区表别改：宏 / 按键重映射 / 方案 / 灯光 / 校准值都在 `nvs` 分区，
  挪动偏移等于把用户配置全抹掉。

## 蓝牙收发（`src/bt_link.h`）

**蓝牙的收和发只走 `bt_link` 一个模块。** 业务代码不碰分片、不碰终止符、
不碰看门狗，网页那边也只面对同一套规则。改协议必须**两边同时改**
（`src/bt_link.cpp` + `../s3-setting.html` 里的 `BtLink`）。

### 线上格式

一条消息 = 若干片 + 一条收尾标记，**包终止符是 `\r`**：

```
VERB:KEY:<正文片段>\r      0~N 条
VERB:KEY:LEN:<总字节数>\r  流式回复才有，正文第一片之前
VERB:KEY:END\r            每条消息都有（正文 0 字节时也发）
```

- `VERB` / `KEY` 非空、不含 `:` `\n` `\r`
- `KEY` 优先用**请求号**（1~9999），不要拿业务字符串当 key
- 正文按 **UTF-8 字节**算，中文一个字 3 字节

### `LEN:` 那一行不是可选的

`btLinkStreamBegin(verb, key, totalLen)` 的 `totalLen` 会先发成一条
`LEN:<总字节数>`。主机收到 `END` 时拿它和**实际收到的 UTF-8 字节数**对一遍，
对不上就报"传输丢片"、**不把残缺正文交出去**。

原因：分片发送丢片是**静默的** —— 一条 ATT 通知带不下就被协议栈整条丢掉，
而收尾标记照样会到。没有总长做对照时，主机只有"看着像完整的"这一个依据：

- 运气好 → `JSON.parse` 报 `unexpected end of input`（还能看出是丢片）
- 运气不好（正好切在某个 `}` 上）→ **语法合法但缺内容**，页面照着它显示，
  甚至照着它回写，把缺掉的字段静默清零

早期 `bt_link.cpp` 里这里是 `(void)totalLen;`（注释写着"只是诊断信息"），
就是上面第二种情况的来源。改协议时**两边都要认这条行**：网页端把它单独
识别、**不拼进正文**；旧网页遇到它会把 `LEN:xxx` 当正文开头，所以改完要
连页面一起换。旧固件不发这一行，网页端会跳过核对（向后兼容）。

### 固件侧：发

```cpp
btLinkReplyC("REMAPDUMP", body);            // 处理请求的分支里回话（推荐）
btLinkReplyf("GKEYPHASE", "%u", ph);        // printf 风格
btLinkSendC("LOG", "0", "STREAM_ON");       // 推送类：自己指定 key
btLinkStream("LOG", line);                  // 日志流：内部 10Hz 节流 + 给响应让路
// 大块（几 KB）：StreamBegin / Write / StreamEnd，正文不进队列
```

`btLinkSend*` 只是**入队**。真正 notify 发生在 `btLinkPoll()`（loop() 里），
每轮最多 `BT_POLL_BUDGET_MS` 毫秒、片间喂一次狗。

### 固件侧：收

```cpp
void onWrite(...)  { btLinkOnWrite(bytes, len); }   // 回调里只有这一行
void loop()        { btLinkPoll(); logDumpPump(); } // 派发 + 流式回拉
```

`btLinkPoll()` → `handleCommand()`，**永远在主任务**，所以 handler 里可以
直接碰 LVGL / NVS / SPI。BLE 回调里绝不解析指令。

### 网页侧

```js
const body = await BtLink.call("MACRODUMP", "MACRODUMP:p0_M1", 800);  // 发+等
BtLink.on("LOGDUMP", body => { ... });                              // 推送
```

## 配置 JSON（CFG\*，schema v3）

**键盘里存的配置，收和发都走这一份 JSON。** 网页上那个"配置 JSON"文本框
是它的原文；连上蓝牙会自动拉一次，上面所有配置表单随之填成真实值。

### 线上协议

和 bt_link 是同一套链路，没有另开通道：

```
主 → 键盘   CFGBEGIN:<总字节数>        开一段接收（整份）
           CFGPATCH:<总字节数>       开一段接收（增量，见下）
           CFGDATA:<正文片段>           每片 ≤ CFG_RX_CHUNK_MAX(200) 字节
           CFGEND#<请求号>             收尾（整份）
           CFGPATCHEND#<请求号>        收尾（增量）
键盘 → 主   CFGDUMP:<请求号>:LEN:<总字节数>   长度握手（见下）
           CFGDUMP:<请求号>:<片段> ×N   正文完整
           CFGDUMP:<请求号>:END         收尾标记
           CFGSAVE:<请求号>:OK:<项数>:<毫秒>   或   ERR:<原因>
           CFGSAVE:<请求号>:OK:<项数>:<毫秒>:PARTIAL:<失败数>:<键名>
           CFGERR:<原因>                整条请求被拒（内存不够 / 链路忙 / JSON 生成失败）
```

⚠ `PARTIAL` **不是**失败：值已经写进 RAM 并提交了，键盘当场就是新的，但有
若干项**没存进 flash**，断电会丢。原因是 `Preferences::put*` 写不下新键时
**静默失败**（返回 0），而 `nvs` 分区只有 20KB 且是只增不减的日志结构。所以
这一条必须如实报出来 —— 让"保存成功"真的等于"存住了"。

### 增量：只改其中几项

网页上每个控件单独保存时走这条路，不走整份。收包流程和整份**完全一样**，
区别只在收尾时传给 `cfgApplyDoc` 的 `isPatch` 标志。

```
CFGPATCH:<总字节数>
CFGDATA:<正文片段> ×N
CFGPATCHEND#<请求号>       正文 = 整份 JSON 的一个子集
```

子集的语义**逐条与整份一致**：

| 出现的东西 | 含义 |
| --- | --- |
| `"disp_mode": 2` | 写这一个标量 |
| `"windows": { "remap": [...] }` | **整份替换** Windows 的映射（`[]` = 清空） |
| `"mac": { "macros": { "M7": "SEQ:x" } }` | 写这一个宏（`null` = 删） |
| `"gkeys": { "MAa": "SW:1+CMB:128,4" }` | 写这一个全局键（`null` = 删） |
| 没出现 | **不动** |

⚠ 增量**不带 `version`**，也**不做版本闸门**：补丁的语义本来就是"只动我点名
的那些"，老网页打过来的补丁顶多少改几项，不该整份拒掉。要对齐版本走整份那条路。

⚠ 删一个键必须显式发 `null` —— 补丁里"键不存在"的意思是**不动它**。网页那边
靠"在深拷贝上跑一遍 mutator、再和当前模型求差"来生成补丁，所以删除天然会变成
`null`。

为什么值得单开一条路：改一项（比如只切显示风格）本来要传几 KB，键盘那边收几百
毫秒，网页传完还要再整份拉回来确认一趟 —— 改成补丁后是几十字节，而且**不带
`disp_mode` 就不会挂整屏重建**。

正文里**绝对不能有 `\n` / `\r`** —— 接收侧按行攒，混进换行会被切成多条
指令，JSON 被劈成两半。网页那边用 `JSON.stringify`（不带缩进）压成一行。

⚠ `LEN:` 握手行不是可选的诊断信息，而是**协议依赖项**。正文是分片发的，而
**丢片是静默的**：一条 ATT 通知带不下就被协议栈整条丢掉（`BT_PAYLOAD_MAX`
是 20，协商失败时正好是上限），而收尾标记 END 照样会到。主机手里没有总长就
只有"看着像完整的"这一个依据，于是可能拿一份正好切在某个 `}` 上的残缺正文
去 `JSON.parse` —— 那是**语法合法但缺内容**的配置，页面照着它显示、甚至
照着它回写，把缺掉的部分清零。有了总长，主机在收到 END 时按 **UTF-8 字节数**
对一遍，对不上就明确报"传输丢片"而绝不交付。

⚠ `LEN` 与正文首片是**连在同一个 body 里**发出的，不是独立一行 —— 20 字节
预算下每片正文只有 9 字节（`chunkRoom` = 20 − 头长 10 − 1），而 `LEN:20480`
加换行要 10 字节，独立成行会把这一行从中间切开、主机再也拼不回完整的
`LEN:20480`。主机侧必须把 `LEN:356{"version":2,...` 这种粘连形态一起认掉。

### v3 的内容

```jsonc
{
  "version": 3,              // 版本闸门，不等于 3 就整份拒绝
  // 十三个标量
  "disp_mode": 0, "saver_mode": 0, "curr_prof": 0,
  "light_on": true, "brightness": 128, "effect": 0,
  "ind_level": 2, "key_fx": 0,
  "alarm_on": false, "alarm_h": 7, "alarm_m": 30,
  "sht_offset": 0.0, "set_epoch": 1730000000,

  // 方案块：按操作系统分，不再是 remap[4] + 顶层 macros
  "windows": {
    "remap":  [ {"from":224,"to":227} ],       // 定长：一个都没配就是 []
    "macros": { "M1": "SEQ:ab", "M2": "CMB:128,4" }   // 稀疏，没设的不出现
  },
  "mac": {
    "remap":  [],
    "macros": { "M7": "SEQ:1234567891" }
  },

  // 全局键留在顶层，不分系统
  "gkeys":  { "MAa": "SW:1+CMB:128,4", "MA_ph": 0, "MB_ph": 0 },

  // 倒计时：只读
  "timer":  { "run": true, "remain": 3661, "total": 3661 }
}
```

#### 方案从 4 个改成 2 个

方案这一维度不再是"四个玩法档"，而是**按操作系统分**：`windows` 和 `mac`。
`TOTAL_PROFILES` 相应地从 4 改成 2。

**NVS 键名一个都没改**：方案 0 仍然是 `p0_*` / `rmp_0_*`，方案 1 仍然是
`p1_*` / `rmp_1_*`。也就是说"方案 0 = Windows、方案 1 = macOS"只是给已有的
0/1 重新起了名字，**里面已经配好的 remap 和宏原样接着用**。p2/p3 的数据留在
NVS 里但固件不再读取（用户明确要求彻底废掉）—— 键还占着分区，但 NVS 本来
就只增不减，留着旧键并不占新键的位置。

⚠ 开机读 `curr_prof` 时**必须钳位**：NVS 里很可能还躺着旧固件写的
`curr_prof = 2` 或 `3`，不钳位就会越界去索引 `profileRemaps[2]`。已在
`setup()` 里加上并记一条告警。

`profile_icons.h` 里的四个图标本来是 win / mac / game / work，砍到 2 个之后
正好剩 win + mac，语义天然对上；`profile_icon_get()` 自带越界保护，那个头文件
不用动。

#### 宏键名：JSON 里不带系统前缀

v2 的 `"p0_M1"` 在 v3 里写成 `"M1"` —— 块名已经说明了是哪个系统，前缀是冗余的。

| JSON 键 | 所在块 | 结果 |
|---|---|---|
| `"M7"` | `windows` | 存成 `p0_M7` |
| `"M7"` | `mac` | 存成 `p1_M7` |
| `"p0_M7"` | `windows` | 放行（老 JSON 兼容），存成 `p0_M7` |
| `"p1_M7"` | `mac` | 放行，存成 `p1_M7` |
| `"p0_M7"` | `mac` | **拒绝** |

最后一条是故意的：`"p0_M7"` 出现在 `mac` 块里几乎一定是"从 Windows 那段复制
过来忘了改"。默默存成 mac 的 M7 等于"按了 M7 结果 Windows 的宏跑在了 mac 上"，
而页面上看不出任何异常 —— 那比直接报错难查一百倍。

另外**拒绝前导零**（`M01`）：它按十进制解析等于槽 1，能过范围检查，但 NVS 里
存下的键是 `p0_M01`，而 `executeMacro` 读的是 `p0_M1`，两者永远对不上，而且
那把键会留在 NVS 里删不掉。

#### 语义：四个字段的规则各不相同

| 字段 | 出现 = | 空值 = | 没出现 = |
|---|---|---|---|
| `<块>.remap` | 该系统**整份替换** | `[]` = 清空这个系统 | 这个系统不动 |
| `<块>.macros.<键>` | 写这一个宏 | `null` / `""` = 删掉它 | 这个宏不动 |
| `gkeys.<槽>` | 写这一项 | `null` / `""` = 删掉它 | 这一项不动 |
| `timer` | — | — | — |（**只读**，见下） |

- `remap` **定长**：一个规则都没有时也要发 `[]`。缺项的话"这个系统没规则"
  和"这个系统没提"分不开，而后者按本模块的规矩是"不动"，于是"清空某个系统"
  根本清不掉。
- `macros` **稀疏**：24 个键全发光键名就 200 多字节，而绝大多数人只设了三五个。
  **删掉一行 JSON 就是删掉一个宏。**
- `MA_ph` / `MB_ph` **永远发**：0 是合法值，"没这个键"和"相位是 0"必须分得开。
- `gkeys` 留顶层、不进 windows/mac：MA/MB 是"按一下换一套动作"的全局键，和
  当前跑在哪个系统没关系；拆成两套只会让 NVS 多占一倍、页面多出一倍卡片。

#### timer：进 JSON，但**只读**

`cfgBuildJson` 每次拉取时现报 `{run, remain, total}`，所以页面上看到的是键盘
此刻真在跑什么。`cfgApplyJson` 收到它会**原样忽略**：不写 NVS、不改运行状态。

这是有意的。倒计时本来就是运行内存里的一次性倒数（`TIMERSET:` 设、跑完归零、
断电归零）。落盘会带来两个坏处：断电重启后倒计时"复活"了而用户以为它已经随
断电结束；以及每次打开网页点任意一个"保存"都会把这个快照写一遍，把一个纯
运行时的量伪装成配置 —— 那比没有这个字段更容易误导。`TIMERSET:` 通道保留。

### 容量

接收缓冲不是 .bss 固定数组了，是 `ps_malloc` 的 `CFG_BUF_SIZE`(20480) × 2
（收发各一份，`setup()` 里就分配好）。方案砍到 2 个之后最坏情况降到约
**8.5KB**（24 个满宏 + 2×32 条满映射 + 满全局键），余量很宽。典型配置
几百字节、2~3 片就发完。

### 故意**不**进 JSON 的东西

| | 原因 |
|---|---|
| **ME 键文本** | 可能十几 KB 且要转 hex，本来就走的二进制通道 |
| **壁纸** | JPEG 裸字节（含 0x00），按行攒会碎成渣 |
| **日志 / 告警** | 运行时事件，不是设置 |

这三个各自保留原来的 `ME_*` / `LOGO_JPEG_*` / `LOG:*` 通道。

### 老协议还在

`REMAP:` / `SET:` / `GSET:` / `GKEYDUMP:` / `MACRODUMP:` / `REMAPREAD:` /
`GKEY_RESET:` / `MACROS_RESET:` / `REMAP_RESET:` / `DISP_MODE:` / `TIME:` /
`ALARMSET:` 这些指令**固件里仍然全部保留**，老页面/老脚本还能用。网页这边
的保存按钮已经全部改走 JSON，但删掉老指令是下一步的事（要先确认没有别的
工具在用它们）。

⚠ **remap 的写入路径两边共用 `cfgStoreRemap()`**（一个函数）。共用是故意的：
两条路必须落出完全一样的 NVS 布局，否则用户在 JSON 里改一遍、再用老协议存
一遍，两边会互相覆盖出不同结果，而现场没有任何异常。

### 踩过的坑（改协议前先读）

- **单条通知能带多少字节 = 协商后的 ATT MTU - 3。协商失败时（手机端浏览器
  常见）只有 20 字节，超出的不是被截断而是整条被协议栈丢掉。** 症状统一是
  "网页只等得到超时，然后误以为键盘里是 0 条配置"。这解释了那个一直归因错的
  不对称：1 条规则整行 20 字节能过、2 条 28 字节就丢。
  ⚠ 别用 `BLEDevice::getMTU()` 算预算：它返回 `m_localMTU`（`setMTU(517)`
  自己设的本地值），不是协商结果。
- **分片之后不能一口气同步推完。** 8KB 日志按 20 字节一片是 400+ 片，
  同步推完要把主循环按住 8 秒；loop() 挂在任务看门狗上（10 秒、panic），
  再多几条就是"回拉日志把键盘搞重启"。所以发包摊到多次 loop 上。
- **收尾标记 `END` 那一包本身也必须装得下 20 字节。** `MACRODUMP` + 业务 key
  `p3_M12` 正好 21 字节 → 整条丢掉 → M10~M12 的宏读不回来，而且日志里什么
  异常都没有。这就是 key 必须用请求号的原因。
- **包终止符用 `\r` 不用 `\n`。** `\n` 得留给正文当数据 —— LOG 回拉整个
  就是一堆换行分隔的行，用 `\n` 收尾的话日志面板里 8KB 历史会挤成一大行。
- **必须用流式 TextDecoder（`{stream:true}`）。** 一片 20 字节，一个汉字 3
  字节，分片完全可能从汉字中间切开，非流式解码会吐一串 U+FFFD 豆腐块。
- **"正文为 0 字节"必须表达成"只有一条 END"。** 读一个空方案、读一个没设的
  宏，"读到了、确实一条都没有"是有意义的结果；沉默会被网页当成"读不到"。
- **关键响应和日志流抢同一条通道，而通知不排队。** `btLinkSend*` 入队时会开
  一小段独占窗口（`BT_CRITICAL_HOLD_MS`），期间日志流自动让路。
- 空闲兜底提交从 15ms 放宽到 **80ms**（`BT_LINE_IDLE_MS`）：Web Bluetooth 的
  `writeValue` 会按协商出来的 MTU 拆包，15ms 会在同一个 `writeValue` 的两个包
  之间误判成"这条发完了"，29 字节的 `REMAP:0:clear:224,227;227,224` 被当成
  两条命令收下 → "下发 2 条只存进 1 条"。
- **"值真的变了才做副作用"这个优化，绝不能用"再比一次当前值"来判。**
  `cfgApplyDoc` 是三遍结构：第一遍校验、第二遍赋值 + 落盘、第三遍算
  `pendMask`（决定要不要 `settimeofday` / 重建主屏 / 切方案 / 换屏保）。
  第三遍如果写成 `if (*f->var == pend[i].num) continue;`，那它比较的**已经是
  第二遍刚写进去的新值**了 —— 永远相等，于是 `pendMask` 恒为 0，**四类副作用
  一个都挂不上**。
  症状特别有欺骗性：网页回 `已保存 1 项`、NVS 里也真写进去了、`cfgModel` 也
  更新了，唯独屏幕上什么都没发生 —— "同步电脑时间"报成功但钟不跳，切显示风格
  报已更新但风格不变。
  ⚠ 更坑的是它**顺带修好了另一个 bug**：网页全量下发时"改个亮度也带着
  disp_mode"，于是每次都重建主屏（"改个亮度键盘自己跳设置页"）。副作用被整体
  掐掉，这个现象自然消失了，看起来像修好了。所以真修法是让第三遍**读第二遍记
  下来的 `pend[i].changed`**，而不是再比一遍 —— 两件事必须一起做，只做一个都会
  坏。

### 换 MTU 预算要连带改的地方

`BT_PAYLOAD_MAX`（默认 20）改大之前，先确认协商结果真的拿得到；拿不到就维持
20。要接协商值的话用 `pServer->getPeerMTU(conn_id)`，**不要**用
`BLEDevice::getMTU()`。
