# 字体方案

## 现状

已使用 `bake_fonts.ps1` 烘焙思源黑体 SC 子集，输出到 `deps/` 目录：

| 文件 | 字重 | 字号 | 用途 |
|------|------|------|------|
| `deps/lv_font_sans16.c` | Regular | 16px | 正文、标签 |
| `deps/lv_font_sans20.c` | Regular | 20px | 日期显示 |
| `deps/lv_font_sans28.c` | Regular | 28px | 标题（备用） |
| `deps/lv_font_sans_bold48.c` | Bold | 48px | 时钟大字 |

子集字符数：268 个（ASCII 可打印 + 全角标点 + 项目专用汉字）

字体文件放在 `deps/`（sketch 目录之外）避免被 Arduino 独立编译成多份，导致链接时 multiple definition 错误。

烘焙好的字体已集成到 `lvgl_demo.ino`：
- `lv_conf.h` 中 `LV_FONT_CUSTOM_DECLARE` 已声明四个字体
- `lvgl_demo.ino` 顶部已 `#include "../deps/..."` 引入四个 .c 文件
- `build_ui()` 中 Montserrat 字体引用已替换为对应中文字体
- 每个字体 .c 内部的所有静态变量（`glyph_bitmap`、`glyph_dsc` 等）均有独立后缀（`_16`/`_20`/`_28`/`_bold48`），跨文件不冲突

## 重新烘焙

若修改了中文字符集，管理员重新运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\bake_fonts.ps1
```

**注意**：脚本内部通过 Node.js 子进程调用 lv_font_conv，绕过 PowerShell 的参数解析问题。

## 字体来源

- [思源黑体简体中文](https://mirrors.tuna.tsinghua.edu.cn/adobe-fonts/source-han-sans/OTF/SimplifiedChinese/)（清华 TUNA 镜像）
- 字重：Regular（正文）、Bold（标题/时钟）
