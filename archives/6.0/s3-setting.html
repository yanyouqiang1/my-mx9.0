📖 这份 JSON 到底包含什么 / 怎么发回去的（点开看）
键盘里存的配置会拼成一整份 JSON。下面这个框就是它的原文， 连上蓝牙时会自动拉一次，另外两个页签上所有配置表单（显示风格 / 闹钟 / 方案 / 映射 / 宏 / 全局键）都会随之填成键盘里的真实值。

整个页面只有这一份配置：在表单里改、在下面的框里手改， 读写的都是同一条路 —— 改模型，再发回键盘。所以「从键盘拉取」 一次就等于以前的「一次性预加载全部」（那个按钮原来是 54 条指令、 要跑 30 秒，现在是一次往返）。

怎么发回去的：
· 上面每个控件单独保存时，只发这次改动的那几项（几十字节）， 键盘上其它配置一个字节都不动。顺带也解决了"改个亮度键盘自己 跳到设置页" —— 因为补丁里没带 disp_mode，固件就不会 重建主屏。
· 下面这个框点「💾 保存到键盘」时走整份（你在框里手改了什么 只有你自己知道，差异不可信）。
· 两种发法的语义完全一致：都是"框里有的才动，没写的不动"。

包含什么：
· 十三个标量设置：显示风格、屏保、当前方案、背光、亮度、灯效、 状态灯亮度、按键特效、闹钟开关/时/分、温度偏移、时间
· windows / mac 两个方案块，每个块下面 挂这个系统自己的个性化配置：
  · remap：按键映射，一个数组，元素是 {"from": 键码, "to": 键码}；没配就写 []
  · macros：M1~M12 共 12 个宏，形如 "M7": "SEQ:abc"；键名不带系统前缀，块名已经说明了是哪一边。 没设过的宏不会出现在 JSON 里，所以删掉一行就是删掉一个宏
· gkeys：MA/MB 老单套、 MAa/MAb/MBa/MBb 双状态、 M1~M12 各自挂的全局动作， 以及 MA_ph/MB_ph 两个相位（永远存在，0 或 1）。 它留在顶层、不分系统 —— 这些是"按这颗键额外做什么"的全局键， 和当前跑在哪个系统没关系
· timer：倒计时当前状态（run / remain / total）。只读：保存时固件会把它原样忽略， 既不写 NVS 也不改正在跑的倒计时 —— 放进 JSON 只是为了让你看得到 键盘此刻在跑什么；它本来就是断电归零的运行时状态，落盘反而会 让"重启后倒计时复活"

不包含（各有原因，故意保留自己的通道）：
· ME 键文本 和 壁纸 —— 前者可能十几 KB 要转 hex、 后者是 JPEG 裸字节，本来就走的二进制通道，塞进 JSON 没意义
· 日志 / 告警 —— 那些是运行时事件，不是设置

几个约定：
· version 是版本闸门，不能改。固件只认它自己那一个版本号 （当前 v3），改成别的会被整份拒绝并提示"版本对不上，请重新拉取"。
· 没写的字段保持原样（不会被清零），所以可以只改一个数再存。
· 超出范围的字段会整份拒绝并告诉你错在哪一项，不会偷偷夹取值 —— 比如 brightness 只接受 0~255。
· 不认识的字段会被忽略（所以网页比固件新时也能用）。
· remap 是唯一的例外：它一旦出现就是整份替换 （写成 [] 就是清空那个系统）。
· macros / gkeys 是逐键的：出现 = 写这一条， 值给 null 或 "" = 删这一条，不提 = 不动。
· 宏键名里可以带老的 p0_ 前缀（"p0_M7"）， 但它必须和所在块对得上 —— 写在 mac 块里的 "p0_M7" 会被拒绝，因为那几乎一定是复制 Windows 那段忘了改。写成 "M7" 最省事。
· 点保存时固件会显式提交 flash，所以"已保存"之后断电也不会丢。 但如果 nvs 分区满了装不下新键，固件会**如实告诉你哪几项没存住** （状态栏 + 弹窗点名），因为那种情况下键盘当场是新配置、**断电会丢**。 · 这些值仍然存在原来那套 NVS 键里（p0_* / p1_*）， 不会清掉你已有的按键映射和宏：Windows 就是原来的方案 1， macOS 就是原来的方案 2。原来方案 3/4 的数据还留在 NVS 里， 但固件不再读取它们。
